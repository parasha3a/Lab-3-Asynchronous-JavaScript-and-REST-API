# Лабораторная работа №3 — Асинхронный JavaScript и REST API

Приложение «Доска публикаций»: загрузка публикаций с JSONPlaceholder (GET) и создание новой публикации (POST) без перезагрузки страницы.

## Запуск

1. Откройте `index.html` в современном браузере (Chrome, Firefox, Safari, Edge).
2. Нужен доступ в интернет: данные берутся с `https://jsonplaceholder.typicode.com`.
3. Установка и сервер не нужны.

Файлы проекта:

- `index.html` — разметка: кнопка загрузки, список, форма с полями «Заголовок» и «Текст», область сообщений.
- `style.css` — оформление, адаптивная вёрстка.
- `app.js` — логика: fetch, async/await, валидация, обработка ошибок.

## Реализованные функции

1. **Интерфейс.** Кнопка «Загрузить публикации», список публикаций, форма с подписанными полями «Заголовок» и «Текст», кнопка «Создать публикацию», область сообщений.
2. **GET-запрос.** По кнопке выполняется `fetch` на `https://jsonplaceholder.typicode.com/posts?_limit=5` через `async/await`. Проверяется `response.ok`, затем читается JSON. Для каждой из 5 публикаций выводятся ID, заголовок и текст через `textContent`.
3. **POST-запрос.** Перед отправкой заголовок и текст обрезаются `trim()`. Пустые значения (включая строки из одних пробелов) не отправляются, а рядом с полями выводится код ошибки: `EMPTY_TITLE` или `EMPTY_BODY`. Запрос `POST` отправляет `{ title, body, userId: 1 }` в формате JSON с заголовком `Content-Type: application/json`. Обработчик формы вызывает `preventDefault()`. При успехе публикация добавляется в начало списка, а сообщение показывает код ответа (`201`), ID и заголовок из ответа. При загрузке сообщение показывает код ответа (`200`) и число публикаций.
4. **Загрузка и ошибки.**
   - Во время запроса выводится сообщение «Загружаем…» или «Отправляем…», кнопка блокируется, чтобы не отправить запрос дважды.
   - В `finally` кнопка снова разблокируется при любом исходе.
   - Ошибки обрабатываются через `try/catch`:
     - обрыв сети (`fetch` отклоняется): код `NETWORK_ERROR`;
     - HTTP-ошибка (`response.ok === false`, например 404): код самого статуса, например `404`;
     - некорректный JSON: код `PARSE_ERROR`.
   - В сообщении выводится только код ошибки, например «Код ошибки: 404». Код хранится в свойстве `error.code`, которое создаёт функция `createError`. Пустая форма даёт код `FORM_INVALID` в области сообщений, а каждое пустое поле — свой код (`EMPTY_TITLE`, `EMPTY_BODY`) под полем.
   - После ошибки введённые данные формы сохраняются, поэтому можно сразу повторить отправку.

## Проверка работы

Проверка выполнена автоматически: `index.html` и `app.js` загружались в DOM-окружении jsdom, запросы шли к реальному API JSONPlaceholder. Для имитации 404 и обрыва сети запросы подменялись в окне. Всего 42 проверки, все пройдены.

| Пункт задания | Что проверялось | Результат |
| --- | --- | --- |
| Загрузка (GET) | Кнопка блокируется во время запроса, выводится 5 публикаций с ID, заголовком и текстом, сообщение об успехе | Пройдено |
| Пустые поля | Пустые поля и строки из пробелов: ошибки под полями, запрос не отправляется | Пройдено |
| Создание (POST) | Отправлены заголовок и текст без пробелов по краям, `userId: 1`, `Content-Type: application/json`; публикация появилась первой в списке; сообщение с ID; форма очищена | Пройдено |
| HTML в тексте | Введённый `<b>…</b>` выводится как текст, а не как разметка | Пройдено |
| 404 на GET | Адрес заменён на `/postz`: сообщение «Код ошибки: 404», кнопка снова активна, повторная загрузка работает | Пройдено |
| Обрыв сети на POST | Сообщение «Код ошибки: NETWORK_ERROR», данные формы сохранены, повторная отправка успешна | Пройдено |
| Обрыв сети на GET | Сообщение «Код ошибки: NETWORK_ERROR», кнопка снова активна, список пуст | Пройдено |

Ручная проверка по пунктам задания: адрес GET-запроса можно временно заменить на `https://jsonplaceholder.typicode.com/postz` в `app.js` (константа `POSTS_URL`). После проверки верните `posts?_limit=5`.

Примечание: JSONPlaceholder имитирует создание публикаций. Новые записи не сохраняются на сервере, поэтому ID в ответе всегда `101`.
